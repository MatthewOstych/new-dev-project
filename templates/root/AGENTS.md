## Правила лежат рядом с кодом

Этот файл держит то, что действует везде. Правила подсистемы лежат в `AGENTS.md`
её папки, причины к ним в `Documentation [{{PROJECT}}]/`. **Прежде чем трогать папку
из таблицы, прочитай её `AGENTS.md`.**

Claude Code читает `AGENTS.md` только через импорт, поэтому рядом с каждым лежит
`CLAUDE.md` из одной строки `@AGENTS.md`. Новый `AGENTS.md` заводится вместе с
таким `CLAUDE.md` и строкой в таблице выше. Свой `AGENTS.md` получает крупный
сервис, модуль бэка со своими правилами, большой отдельный компонент,
интеграция.

## Главные правила

1. **Без заглушек.** Не создаём функции-заглушки, «примерные» экраны, фейковые
   данные. Папка без кода держится своим `AGENTS.md` или `.gitkeep`.
2. **Зависимости сверху вниз.** Обратных стрелок нет, границы держит линт
   или тест:
   - веб: app → services → API бэка; <!-- [web] -->
   - бэк: routes → service → repository, чужой модуль только через `index.js`; <!-- [railway] -->
   - функции: `index.ts` → фича → `shared/`; <!-- [firebase] -->
   - мобилки: views → viewModel → services → model.
3. **UI только из библиотеки своей платформы** (`src/ui` на вебе, `ui/` в
   мобилках). Повторилось второй раз: сразу в библиотеку.
4. **Потолок 500 строк кода на файл** на всех платформах
   (`scripts/check-file-size.mjs`, eslint, SwiftLint, detekt). Упёрся: резать,
   а не поднимать порог.
5. **Язык.** По-английски код, идентификаторы, тексты интерфейса, ошибки,
   коммиты. По-русски комментарии «почему», `AGENTS.md`, документация.
   Комментарий объясняет почему, а не что. Без длинных тире в тексте для людей.
6. **Секреты** не печатаются и не коммитятся. Ключи CLI приходят из `.envrc`
   (direnv), значения бэка из `.env` пакета, `.env.example` перечисляет только
   имена.
7. **Документация правится в той же задаче, что код**, когда меняется
   устройство, контракт или причина. Правила: `Documentation [{{PROJECT}}]/CLAUDE.md`.
8. **Большая задача** получает заметку в `Documentation [{{PROJECT}}]/tasks/`
   (`blocking/`, `bugs/`, `additions/`) только с согласия владельца. Скилл
   `/task-note`.
9. **Документация и задачи обновляются только в `{{MAIN_BRANCH}}`** и сразу
   подтягиваются во все остальные ветки, на какой бы ветке ни шла работа.
   Процедура в разделе ниже.

## Документация и задачи в `{{MAIN_BRANCH}}`

Это `Documentation [{{PROJECT}}]/` и раздел «Реестр задач» этого файла. Все ветки
должны видеть одни и те же задачи и одно описание устройства, иначе доки
расходятся и конфликтуют при слиянии.

- Правка коммитится сразу в `{{MAIN_BRANCH}}` отдельным коммитом: только доки и
  реестр, без кода, сообщение по-английски (`docs: …`). Этот коммит правило
  разрешает без отдельной просьбы. Пуш только по просьбе.
- Код, который описывают доки, остаётся в своей ветке и попадает в
  `{{MAIN_BRANCH}}` обычным слиянием.
- В других ветках правки доков не коммитятся, они приходят туда только
  слиянием из `{{MAIN_BRANCH}}`.

Если ты не на `{{MAIN_BRANCH}}`:

1. Открыть `{{MAIN_BRANCH}}` отдельной рабочей папкой:
   `git worktree add ../.{{SLUG}}-main {{MAIN_BRANCH}}` (если она уже где-то
   открыта, работать там). Текущую папку не переключать: в ней незакоммиченный
   код и запущенный `npm run dev`.
2. Перенести туда правку доков и строк реестра, закоммитить там.
3. В текущей ветке выбросить свою копию правки
   (`git checkout -- 'Documentation [{{PROJECT}}]'`, строки реестра так же) и
   сделать `git merge {{MAIN_BRANCH}}`.
4. Все остальные локальные ветки: `git -C <её рабочая папка> merge {{MAIN_BRANCH}}`.
   Ветка нигде не открыта: временной папкой (`git worktree add <tmp> <ветка>`,
   merge, `git worktree remove <tmp>`).
5. Убрать временные рабочие папки. Конфликт при слиянии: остановиться и
   сказать владельцу, молча не решать.

На `{{MAIN_BRANCH}}`: коммит, затем сразу шаги 4 и 5.

## Деплой и сервисы

- Бэк на Railway, веб на Vercel. CLI привязаны через `.envrc`. <!-- [railway] -->
- Бэк на Firebase, веб на Vercel. CLI привязаны через `.envrc`. <!-- [firebase] -->
- **По умолчанию только чтение.** Всё, что меняет деплой, переменные или базу
  прода, делается только по явной просьбе.
- **Никогда не печатай секрет:** называй имя переменной, не значение.
- Аутентификация CLI приходит из токенов в `~/.config/<сервис>-tokens/`, а не из
  глобального `login`. `Unauthorized` значит: проблема в токене, его
  перевыпускает владелец.

## Разработка

- `npm run dev`: база текущей ветки (brew-Postgres), API и веб обычными процессами (не контейнерами) на свободных портах, перезапуск при смене ветки. Адреса печатаются первой строкой. <!-- [railway] -->
- `npm run dev`: веб; `npm run dev:firebase`: эмуляторы на проекте `demo-{{SLUG}}`, без логина и без облака. <!-- [firebase] -->
- Агент запускает dev через превью (`.claude/launch.json`), а не через Bash, и
  не останавливает процесс на занятом порту: это может быть чужой проект.
- Агент входит скриптом (`/dev-login`), продовый код ради этого не меняется. <!-- [railway] -->
