# Вход агентом

Агент не проходит OAuth (Google, Apple) и не знает паролей пользователя, поэтому
доступ выдаётся строкой сессии в локальной базе. Дальше всё делает обычный код:
Better Auth узнаёт сессию по куке или bearer-токену.

```bash
npm run dev-session -- --email agent@local.test
```

Скрипт идёт через `branch-db.mjs`: сессия создаётся в базе текущей ветки.

- Печатает значение куки сессии (имя куки в выводе) и bearer-токен.
- Пользователь с этим email создаётся, если его нет. `--admin` выдаёт роль
  admin для зоны `(admin)`.
- `--revoke` снимает все сессии этого пользователя.
- Скрипт отказывается работать, если `DATABASE_URL` смотрит не на localhost.

## Куда подставить

- Превью веба: поставить куку на `localhost` через `javascript_tool`
  (`document.cookie = "<имя>=<значение>; path=/"`) и открыть страницу зоны.
- API: заголовок `Authorization: Bearer <токен>`.

## Чего не делать

Продовый код ради входа агентом не трогают: ни dev-ручки, ни переменной
окружения, ни ветки «если разработка» в заслонах. Иначе локальное удобство
превращается в дыру, которая едет в прод.
