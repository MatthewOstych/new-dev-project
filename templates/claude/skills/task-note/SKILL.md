# Заметка задачи

Заметка нужна задаче на много шагов или больше одной сессии, чтобы работу мог
продолжить тот, у кого нет контекста. Это не бэклог: закончили, удалили. Архив
держит git. Правила папки: `Documentation [{{PROJECT}}]/CLAUDE.md`.

**Любая правка задачи** (завести, отметить шаг, перенести, закрыть) вместе со
строкой реестра коммитится сразу в `{{MAIN_BRANCH}}` и тут же подтягивается во все
остальные ветки. Процедура: корневой `AGENTS.md`, «Документация и задачи в
`{{MAIN_BRANCH}}`». В рабочей ветке задача не коммитится.

## Завести

1. Предложить пользователю и дождаться явного «да». Без него файл не создаётся.
2. Категория по тому, что задача значит для релиза, папок ровно три:
   - `blocking/`: без этого не релизимся;
   - `bugs/`: продукт работает не так, как обещает;
   - `additions/`: продукта хватает, задача его расширяет.
3. Имя файла `<kebab-case-ключ>.md` описывает цель, а не дату. Ключ уникален на
   весь vault.
4. Содержимое по шаблону ниже. По-русски, без длинных тире.
5. Строка в реестре задач корневого `AGENTS.md` тем же изменением.

## Шаблон

```markdown
# <Название задачи>

**Цель.** Что должно получиться и как понять, что готово.

**Зачем.** Почему это делаем сейчас, что мешает без этого.

## План

- [ ] Шаг 1
- [ ] Шаг 2

## Что выяснилось по дороге

- Дата, находка, как она меняет план.
```

## Подзадачи

Появилась подзадача, которую можно вести отдельно (свой статус, свои находки,
живёт дольше сессии): задача становится папкой.

```
tasks/<категория>/<ключ>/<ключ>.md                головной файл: цель, состояние, список подзадач
tasks/<категория>/<ключ>/<ключ>--<подзадача>.md   одна подзадача, один файл
```

Имя подзадачи начинается с ключа и `--`: имена в vault уникальны. Головной файл
перечисляет подзадачи вики-ссылками. В реестре одна строка на задачу.

## Обновить

- Отметки в плане по мере шагов.
- Находка, меняющая план, идёт в «Что выяснилось по дороге» с датой.
- Задача сменила смысл (баг оказался блокером): файл переезжает в другую
  категорию тем же изменением, что строка реестра.

## Закрыть

1. Причины принятых решений переезжают в постоянную документацию
   (`architecture/`, `db-scheme/`). Заметка ничего не архивирует.
2. Спросить пользователя ещё раз перед удалением.
3. Удалить файл (или папку задачи) вместе со строкой реестра.
