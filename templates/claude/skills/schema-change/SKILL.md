# /schema-change <что меняем>

Миграция без заметок в `Documentation [{{PROJECT}}]/db-scheme/` считается
незавершённым изменением. Порядок шагов ниже делает это невозможным пропустить.

## 0. Нужна ли колонка вообще

Факт, который выводится из существующих данных (статус другой строки, дата,
счётчик), второй раз не хранится. Новая колонка заводится, когда факт нельзя
вывести.

## 1. Развилка

`npm run db:fork-check`. Если в другой ветке есть миграция, которой нет здесь,
сначала влить ту ветку: иначе обе получат один номер, а миграция со старшим
`when` на проде заставит мигратор молча пропустить нашу. `db:generate` делает
ту же проверку сам и не запустится, пока развилка есть. Хук после правки схемы
уже сказал, есть ли она.

Своя миграция уже сгенерирована и никуда не слита, а развилка случилась:
удалить её SQL, снимок и запись журнала, влить чужую ветку, сгенерировать
заново. Базу ветки следующий `npm run db:migrate` пересоздаст сам.

## 2. Схема и миграция

1. Правка `{{DB_DIR}}/src/schema/<домен>.ts`: таблица принадлежит одному
   модулю бэкенда (модуль потом можно вынести в отдельный сервис), `snake_case`
   явно, даты `timestamptz`, FK с явным `onDelete`. Комментарий у колонки
   объясняет, почему она такая, по-русски.
2. `npm run db:generate`. Прочитать сгенерированный SQL целиком, имя миграции
   не менять, SQL руками не править. Лишний `DROP` или неожиданный `ALTER`:
   остановиться и разобраться со схемой. drizzle-kit спросил про
   переименование: ответить осознанно, «create + drop» теряет данные.
3. `npm run db:migrate` применяет миграции к базе текущей ветки.
4. `npm run typecheck`.

## 3. Заметки db-scheme тем же диффом

`Documentation [{{PROJECT}}]/db-scheme/`:

- заметка домена: таблица, колонка, зачем она, какой модуль пишет, кто читает;
- `02. Карта связей`, если появился или изменился внешний ключ;
- `03. Справочник enum'ов`, если менялся словарь.

Вики-ссылки без пути: `[[Имя заметки]]`.

## Что не считается изменением схемы

Правка запроса в репозитории без изменения таблиц. Документация описывает
таблицы, а не запросы.
