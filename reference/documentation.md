# Documentation [Name]

Формат accounting: vault Obsidian, вики-ссылки без пути, правится в той же
задаче, что код, правила, а не хроника. **Доки и задачи коммитятся только в
основную ветку и сразу подтягиваются во все остальные** (раздел «Документация и
задачи в `{{MAIN_BRANCH}}`» в `templates/root/AGENTS.md`, отсылки в
`templates/docs/CLAUDE.md` и `/task-note`). Правила папки:
`templates/docs/CLAUDE.md` → `Documentation [Name]/CLAUDE.md` (+ `AGENTS.md`
с тем же текстом не нужен: папку читает Claude, файл подхватывается сам).

## Раскладка

```
Documentation [<Name>]/
  CLAUDE.md
  architecture/
    00. Архитектура.md                 templates/docs/00. Архитектура.md (вход)
    01. Основы/
      01. Основы.md                    вход раздела
      Слои и правила.md                стрелки зависимостей, линт-границы и почему они там
      Окружения и деплой.md            env по пакетам, Railway/Vercel/Firebase, direnv, кто что деплоит
    02. Веб/02. Веб.md                 зоны, фича как папка, библиотека UI
    03. Сервисы веба/03. Сервисы веба.md   клиент или сервер, двери
    04. Backend/04. Backend.md         модули, аутентификация, миграции, worker
    05. iOS/05. iOS.md                 слои, координаторы, SwiftLint-правила
    06. Android/06. Android.md         слои, навигация, Konsist
    07. Интеграции/07. Интеграции.md   таблица: сервис, статус (заготовка / отложен / работает), где папка, где ключи
    08. Потоки/08. Потоки.md + Поток регистрации и входа.md
    99. Служебное/99. Реестр покрытия.md   папка → заметка
  db-scheme/                           только Railway
    00. Схема БД.md                    вход: карта доменов
    01. Соглашения схемы.md            snake_case, timestamptz, FK с onDelete, таблица принадлежит модулю; исключение: таблицы Better Auth от CLI с timestamp без пояса
    02. Карта связей.md                внешние ключи
    03. Справочник enum'ов.md
    Auth. Пользователи и сессии.md     таблицы Better Auth: зачем каждая, кто пишет
  tasks/
    blocking/project-init.md           первая задача (SKILL.md, фаза 1)
    bugs/
    additions/
```

Разделы платформ, которых нет, не создаются. В именах заметок нет длинных
тире: правило про тире действует и для них. `backend/AGENTS.md` у Firebase не
заводится, правила бэка живут в `backend/firebase/AGENTS.md`.

В конце фазы `npm run format`: prettier выравнивает таблицы в заметках, и
`prettier --check` в `/gate` должен быть чистым. Пустые папки `tasks/bugs`,
`tasks/additions` держатся `.gitkeep`.

## Что писать на старте

Только то, что уже правда. Каждая заметка короткая (до ~150 строк) и отвечает
на «почему так»:
- решения из init-задачи (почему Better Auth, почему веб только через API,
  почему модуль это будущий сервис, почему база на ветку);
- границы и правила линта с причинами;
- поток регистрации и входа: веб (кука через rewrite), мобилки (bearer, idToken).

Не писать: инвентарь файлов, планы на будущее, описание несуществующих фич.

## Реестр задач

В корневом `AGENTS.md` раздел «Реестр задач»: по подзаголовку на
`blocking/`, `bugs/`, `additions/`, одна строка на задачу:
`[[project-init]]: инициализация проекта`. Задача закрылась, строка удаляется
тем же изменением.
